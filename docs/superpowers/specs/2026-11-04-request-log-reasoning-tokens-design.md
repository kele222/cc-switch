# 请求日志推理 Token 列

在用量统计的请求日志中，于“输出”列之后增加默认显示的“推理”列（数值为推理 Token 数量），沿用现有列开关、数值缩写和悬停完整数值的交互。用户已确认继续此方案。

采用完整数据链路：从代理响应与支持的原生会话用量字段读取推理 Token，保存到可为空的 `reasoning_tokens` 数据库列，并通过请求日志接口返回 `reasoningTokens`。单独添加前端空列无法满足查看实际用量的需求；按文本估算则不能保证准确，因此只展示来源明确上报的计数。

缺失字段及历史日志显示“—”，明确上报零时显示“0”。推理 Token 是现有输出计数的细分，不重复加入总 Token 或费用。数据库迁移保留已有记录，不重置导入游标或推测历史计数。所有翻译目录添加列名。

实施顺序：

1. 增加数据库迁移、代理解析与日志读写字段。
2. 保存会话导入中原生上报的推理计数，保持原有输出与费用口径。
3. 增加表格列、显示开关和翻译。
4. 验证缺失、零值、非零值、显示开关、数据库迁移与数据往返，并执行类型及格式检查。
